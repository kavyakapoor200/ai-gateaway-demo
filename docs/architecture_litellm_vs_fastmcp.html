Technical Flowchart: OpenAPI ➔ MCP

Complete visual flow of Phase 1 (Conversion/Setup) and Phase 2 (Client Execution)

Phase 1 How OpenAPI Converts into an MCP Server (Setup Time)
📄 1. Input: OpenAPI Specification
You provide engineering-ops-api.yaml / .json
paths: { "/issues": { "get": { "operationId": "listIssues" } } }
⚙️ Choose Conversion Engine
Which mechanism converts this spec into MCP tools?
Track A: LiteLLM Native Conversion
1. Config Mount
Mount JSON spec into LiteLLM container
config.yaml: spec_path: /app/specs/...
2. In-Memory Parser
LiteLLM parses paths at startup & lowercases names
Tool: engineering_ops_mcp-listissues
3. Tool Registration
Tool is registered inside LiteLLM Gateway memory
Ready on: http://localhost:4000/mcp
Track B: FastMCP Framework
1. Python Script Call
Call FastMCP SDK with spec & client
FastMCP.from_openapi(spec, client)
2. Standalone SSE Server
Exposes SSE transport on port 8005 with MCP tool schemas
Tool: fastmcp_ops-listIssues (SSE :8005)
3. Upstream Gateway Binding
Gateway config points to FastMCP SSE endpoint
mcp_servers:
http://host.docker.internal:8005/sse
✅ Setup Complete: 47 Tools Unified
All tools are now available behind single gateway endpoint: http://localhost:4000/mcp
Phase 2 What Happens When Client (Claude Desktop) Calls a Tool
🤖 1. Client Trigger (Claude Desktop)
User asks: "Please check open issues using fastmcp_ops-listIssues"
JSON-RPC tools/call: { "name": "fastmcp_ops-listIssues", "arguments": {} }
🛡️ 2. AI Gateway Interception (:4000)
• Authentication: Validates Bearer sk-agent-claude-desktop
• Tool Policy Check: Is listIssues allowed for this key? (Allowed!)
• Audit Ledger: Records execution in DB (user: claude-desktop)
• Zero Data Retention: Ensures no sensitive prompts are persisted.
🔀 3. Gateway Routes the Tool Call
Where is this tool hosted?
If LiteLLM Native Tool:
Direct Outbound HTTP Call
Gateway itself sends HTTP GET over network:
GET /api/v1/issues
http://host.docker.internal:8089
If FastMCP Tool:
SSE Forward ➔ Outbound HTTP Call
Gateway forwards call over SSE to port 8005. FastMCP's HTTP client executes request to target REST API:
httpx.get("/api/v1/issues")
target: host.docker.internal:8089
🎯 4. Target Backend (Mock Service :8089)
Executes business logic and returns HTTP 200 OK with real issues JSON:
[ { "id": "ISS-142", "title": "Memory leak...", "status": "open" }, ... ]
📦 5. Envelope Packaging & Return
Engine wraps HTTP response into standard MCP envelope: isError: false. Gateway delivers it back to Claude Desktop.
